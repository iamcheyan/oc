# Minimal Dialog 嵌入终端技术方案讨论

**日期**: 2025-05-25  
**目标**: 在 minimal 模式的 dialog 中嵌入简单终端，以便运行 yazi、lazygit 等命令行工具

---

## 核心挑战

两个 TUI 程序（OpenTUI 和外部程序）都想独占控制同一个终端资源：

```
Vim TUI (OpenTUI) ──想嵌入──→ 外部 TUI 程序 (yazi/lazygit)
         │                              │
         │         ❌ 冲突！            │
         └──────→ 都想控制同一个终端 ←───┘
```

**冲突表现**:
- 屏幕输出混乱（两个程序同时绘制）
- 键盘输入争夺（两个程序同时监听）
- 光标控制冲突（位置计算错误）

---

## 方案对比

### 方案 1: PTY + 完整终端模拟器

**架构**:
```
┌────────────────────────────────────────┐
│          Minimal Dialog                │
│  ┌──────────────────────────────────┐  │
│  │   OpenTUI Box (作为终端模拟器)    │  │
│  │  ┌────────────────────────────┐  │  │
│  │  │   渲染 PTY 输出            │  │  │
│  │  │   - 解析 ANSI 序列          │  │  │
│  │  │   - 模拟光标移动            │  │  │
│  │  │   - 处理颜色/样式           │  │  │
│  │  └────────────────────────────┘  │  │
│  └───────────┬──────────────────────┘  │
│              │ PTY Master              │
│              ↓                         │
│         外部程序 (yazi/lazygit)         │
│         在 PTY Slave 中运行             │
└────────────────────────────────────────┘
```

**需要实现**:
- ANSI 序列解析器（支持光标移动、清屏、颜色等）
- 终端状态机（光标位置、屏幕缓冲区）
- 键盘事件转发（把 OpenTUI 按键发送到 PTY）

**参考实现**:
- `node-pty`（创建 PTY）
- `xterm.js`（终端模拟，但为浏览器设计，需适配 TUI）

**难度**: ⭐⭐⭐⭐⭐ (高)

**评估**:
- ✅ 功能最完整，支持任意 TUI 程序
- ❌ 工作量巨大（相当于实现 xterm）
- ❌ 性能问题（需要频繁解析 ANSI）
- ❌ 维护困难（各种 TUI 程序的行为差异）

---

### 方案 2: 窗口切换管理

**架构**:
```
┌────────────────────────────────────────┐
│           Vim TUI                  │
│  ┌──────────────────────────────────┐  │
│  │        主会话内容                 │  │
│  │                                  │  │
│  │   按 Space → g → d 启动 lazygit  │  │
│  │                                  │  │
│  └──────────────────────────────────┘  │
│                                        │
│  [按 F12 切换到 lazygit 窗口]           │
│                                        │
│  ┌──────────────────────────────────┐  │
│  │        lazygit 子窗口            │  ← 不是 dialog，而是独立的渲染层
│  │        (全屏或分屏)              │  │
│  │                                  │  │
│  │   完全由 lazygit 控制             │  │
│  │   OpenTUI 只负责"窗口管理"        │  │
│  │                                  │  │
│  │   [按 F12 或 q 返回主会话]         │  │
│  └──────────────────────────────────┘  │
└────────────────────────────────────────┘
```

**实现方式**:
- 类似 tmux 的窗口切换
- OpenTUI 管理多个"窗口层"
- 激活外部程序窗口时，OpenTUI 暂停渲染，让出终端
- 退出外部程序时，恢复 OpenTUI 渲染

**用户体验**:
- 不像 dialog popup，更像"切换应用"
- 但可以通过快捷键快速切换

**难度**: ⭐⭐⭐ (中)

**评估**:
- ✅ 实现相对简单，用户体验好
- ✅ 支持任意 TUI 程序
- ❌ 不是真正的"嵌入"，而是切换

### 方案 3: 简化的 PTY 渲染

**限制**:
```
支持的程序：
✅ yazi - 基本文件浏览
✅ lazygit - 基本操作
❌ vim - 太复杂
❌ htop - 需要实时更新
```

**简化假设**:
- 程序输出基本是静态的或简单列表
- 不需要复杂的光标控制
- 主要是"查看"而非"编辑"

**实现**:
- 捕获程序输出
- 简单解析 ANSI 颜色
- 用 `<text>` 组件逐行显示
- 支持基本的上下导航

**难度**: ⭐⭐ (低)

**评估**:
- ✅ 实现简单
- ❌ 功能受限，很多工具无法正常使用
- ❌ 体验不好

---

### 方案 4: 悬浮终端面板

**架构**:
```
┌────────────────────────────────────────┐
│           Minimal Session              │
│  ┌──────────────────────────────────┐  │
│  │                                  │  │
│  │        消息内容区域               │  │
│  │                                  │  │
│  │                                  │  │
│  ├──────────────────────────────────┤  │
│  │   悬浮终端 (可以 toggle)          │  ← 类似分屏
│  │   $ yazi                         │  │
│  │   [文件列表...]                  │  │
│  │                                  │  │
│  └──────────────────────────────────┘  │
│  ┌──────────────────────────────────┐  │
│  │   Prompt 输入框                  │  │
│  └──────────────────────────────────┘  │
└────────────────────────────────────────┘
```

**实现**:
- 底部面板，可以按快捷键 toggle
- OpenTUI 控制上半部分
- PTY 控制下半部分
- 焦点切换决定键盘事件去向

**难度**: ⭐⭐⭐ (中)

**评估**:
- ✅ 实用性强，类似 VS Code terminal
- ✅ 支持任意命令行工具
- ❌ 不是嵌入 dialog，而是独立面板

---

## 推荐方案

### 短期：方案 4（悬浮终端面板）

**实现要点**:
1. 底部可 toggle 的终端区域（高度可调整，如 30%）
2. 可以运行任意命令行工具
3. 焦点切换决定键盘事件去向
4. 适合 quick file browse、git status 等操作

### 长期：方案 2 + 方案 4 组合

**架构**:
- 支持多个"工具窗口"
- 类似 tmux 的窗口切换
- 每个工具独立运行
- 可以通过 leader menu 快速切换

---

## 为什么不选方案 1

1. **工作量巨大**: 相当于在 OpenTUI 中实现一个完整终端模拟器
2. **ANSI 解析复杂**: 需要支持光标移动、清屏、颜色、样式、滚动等
3. **性能问题**: 需要频繁解析 ANSI 序列并重绘
4. **维护困难**: 各种 TUI 程序的行为差异（vim、emacs、lazygit 等）

---

## 关键决策点

在继续实现前，需要确定：

1. **交互方式**:
   - A) 嵌入 dialog popup（类似现在的 git diff dialog）
   - B) 底部终端面板（类似 VS Code terminal）
   - C) 窗口切换（类似 tmux 多窗口）

2. **使用场景**:
   - A) 快速浏览文件（yazi）然后返回
   - B) 长时间编辑（vim/emacs）
   - C) 两者都有

3. **技术栈选择**:
   - 方案 1 完整终端模拟性能好但开发量大
   - 方案 4 悬浮终端性能好且实用
