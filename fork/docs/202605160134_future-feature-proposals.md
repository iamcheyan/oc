# [202605160134]_未来功能与交互巧思提案

本文档整理了一些旨在提升 `opencode-vim` 开发者体验（DX）的小巧思和潜在功能方向。

## 1. `/copy` - 剪贴板无缝集成

**痛点**：在终端环境中，使用鼠标选取 AI 生成的长代码块非常不便。
**方案**：
- 输入 `/copy`：自动将上一条 AI 回复的所有代码块合并复制到系统剪贴板。
- 输入 `/copy 1`：仅复制第一个代码块。
- **技术实现**：集成 `clipboardy` 等库，在 `handleSlashCommand` 中提取 `replState.lastAssistantMessage`。

## 2. `/review` - 本地 AI Code Review

**痛点**：开发者在 commit 前往往需要自查，但容易产生视觉疲劳。
**方案**：
- 输入 `/review`：AI 分析 `git diff`，输出一份简明扼要的审查报告。
- 重点关注：逻辑漏洞、性能隐患、代码规范。
- **技术实现**：复用 git diff 读取逻辑，但使用专门的“审查员” Prompt。

## 3. `/summary` - 工作进度自动整理

**痛点**：长时间开发后，写日报或给同事同步进度时，难以准确回忆所有细节。
**方案**：
- 输入 `/summary`：AI 结合当前会话的上下文记录（对话 + 工具调用记录）生成一份结构化的工作总结。
- **价值**：将 AI 从“对话者”提升为“工作助理”。

## 4. `/test` - 自动化测试用例生成

**痛点**：写业务逻辑很爽，写单元测试很烦。
**方案**：
- 输入 `/test`：AI 识别当前修改了哪些文件/函数，自动在对应目录下生成对应的 `*.test.ts` 或补充现有测试。

## 5. `/vibe` - 模式与性格切换

**巧思**：根据当前任务紧急程度切换 AI 的回复风格。
- `/vibe fast`：极简回答，只给代码。
- `/vibe tutor`：详细教学，解释每一个步骤。
- **价值**：无需在 Prompt 中反复强调风格要求。

## 6. `/alias` - 自定义快捷命令

**巧思**：开发者常有高频重复的复杂指令。
- 允许用户定义 `/alias fix = "检查并修复当前文件的 lint 错误"`。
- **价值**：打造属于自己的个性化 AI 工具箱。

## 7. `/sh | AI` - Shell 与 AI 的管道联动

**巧思**：真正的 UNIX 风格集成。
- 支持 `/sh npm test | fix`：将测试报错直接管道传给 AI 进行修复。
- **价值**：打破工具链壁垒，实现自动化闭环。

## 8. `/share` - 渲染导出静态页面

**巧思**：将优质的解决问题的过程沉淀为资产。
- 输入 `/share`，生成一个带有语法高亮、美观排版的本地 HTML 报告。
- **价值**：方便团队内分享技术解决方案。

## 9. `/cost` - 实时消耗看板

**巧思**：提供算力消耗的心理预期。
- 实时统计并显示当前 Session 的 Token 消耗和估算成本。
- **价值**：让开发者对模型资源的使用做到心中有数。

---

**说明**：以上功能均可在不破坏上游代码结构的前提下，在 `packages/opencode-vim/` 内部实现。
