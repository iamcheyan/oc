# Docs 目录规范

这个 `fork/docs` 目录专门用于记录 `opencode-vim` (OC fork) 的重大技术变更、架构重构以及深度 Debug 经验。

## 记录原则

对于每一次重大修改，新创建的文档必须包含以下几个核心部分：

1. **为什么要这么做 (Why)**：修改的动机、面临的痛点或用户需求。
2. **这么做的好处 (Benefits)**：修改后带来的性能提升、体验优化或架构解耦等好处。
3. **改了哪些东西 (What Changed)**：具体修改的代码模块、工作流或依赖。
4. **经验与教训 (Lessons Learned)**：在修改过程中踩过的坑、技术难点以及沉淀下来的最佳实践。

## 命名与格式约定

为了保持文档的可读性和时间线索，**每一个文档的开头（标题）必须包含时间戳**。

格式规范如下：
```markdown
# [YYYYMMDDHHMM]_[文档主题]
```

例如：
`# [202605160112]_repl模型切换功能重构记录`

请所有协助维护此 fork 的 Agent 严格遵守此规范，在完成重大变更后，主动在该目录下生成规范的复盘文档。
