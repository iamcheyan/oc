如果对比 TUI 来看，当前 CLI 还有几类明显可补的能力。不是“缺功能就都加”，而是优先补那些能明显提升单兵使用体验、同时又不太破坏 fork 边界的。

  1. 会话内状态可见性再加强
  现在你们已经有 Session / Model / Directory 和部分 slash 命令了，但和 TUI 比，CLI 里“我当前到底处于什么状态”还是偏弱。

  我会优先补这些：

  - /status
    一次显示当前 sessionID、agent、model、thinking、当前目录、是否 share、是否有 pending permission
  - prompt 附近的轻量状态提示
    例如每轮输入前在 dim 行显示当前 agent/model
  - /model、/agent 改完后，不只是打印一句，而是顺手刷新当前状态摘要

  这类能力的价值很高，因为 CLI 没有 TUI 那种持续可视化面板。

  2. 权限请求体验还可以更像 TUI
  现在 permission flow 能用，但对 CLI 用户来说还是有点“弹出来再处理”的感觉。TUI 的优势是上下文更完整。

  可以补：

  - permission 请求时显示最近一条用户输入摘要
  - 显示本次请求来自哪个 tool/task
  - /permissions 或 /approvals 查看本 session 最近的 permission 决策
  - 对 repeated pattern 的 allow 做更清楚的反馈

  这会让 CLI 在工具执行密集场景下更接近 TUI 的可控感。

  3. session/history 能力还偏薄
  TUI 在会话浏览、上下文回看上天然更强，CLI 现在更多还是“当前一轮交互”。

  我建议补：

  - /history
    展示当前 session 最近几轮摘要，而不是只能靠 restore 时被动看
  - /jump <message-id|n>
    跳到某一轮上下文附近导出或回看
  - /last
    快速打印上一轮 assistant 最终正文，不带中间 tool 噪音
  - /copy last
    只复制最后回复，而不是整个会话

  这类功能对 CLI 很重要，因为终端滚屏成本比 TUI 高。

  4. tool 输出视图可以再分层
  现在 CLI 已经能渲染 tool 输出，但信息密度和可读性还没到 TUI 那种“结构化面板”的水平。

  可以做的改进：

  - 默认折叠噪音较高的 tool running 日志
  - /verbose-tools on|off
    控制是否显示中间 tool running
  - completed tool 只显示摘要，必要时再 /inspect <n>
  - 对 read/edit/bash 这类常见工具做更稳定的短摘要模板

  你的 CLI 会更像“回答优先，工具为辅”，而不是被工具日志淹掉。

  5. model / agent 切换还可以更顺手
  现在 /model 切换后要求重启，这个虽然能接受，但和 TUI 相比还是重。

  如果后端允许，后面可以尝试：

  - 新轮生效而不是整进程退出
  - /agent、/model 改完后仅影响后续 turn
  - 明确显示“当前轮使用模型”和“下轮将使用模型”

  如果暂时不能做到热切部分你们已经做了一半。

  6复制导用
  用户很多 取；赖令。

  建议补：

  - /copy last
  - /copy user
    `/transcript  导对话版本，不带工具噪音

  这类功能实现成本通常不高，但常用。

  **7.要更 硬做

  - CLI 强在快速启动、脚本化、低干扰、shell 工作流整合

  所以 CLI 更应该强化的是：

  - 可预测的 slash 命令
  - 明确的当前状态
  - 干净的输出
  - 好用的导出/复制
  - 非交互模式和 shell 集成

  而不是去复刻 TUI 的所有交互层。

  如果只选 3 个我认为最值得做的功能，我会排：

  1. /status + 更清楚的当前会话状态展示
  2. /copy last / /last / 更实用的 history 导出
  3. tool 输出分层控制，例如 /verbose-tools
