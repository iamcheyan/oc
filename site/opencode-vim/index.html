Architecture & Specifications

Rigorous downstream engineering.

Empowering the terminal with Vim while preserving upstream purity. All boundary audits and sync protocols are completely transparent.

1. Autonomous Sync Protocol (AGENTS.md)

Deterministic synchronization pipeline designed for AI maintenance agents and scheduled tasks: environment check, automatic timestamped backup snapshots, upstream rebase, lockfile conflict resolution, and 4 mandatory verification gates.

Read AGENTS.md Protocol ↗View fork/update.sh ↗

2. The Single-Seam Boundary Rule

To prevent downstream code rot and git merge hell, oc-vim enforces a strict rule: only packages/tui/src/app.tsx may touch upstream code to register the component root. Enforced by automated CI audit script fork/check-upstream-seams.sh.

View Seam Allowlist ↗Audit Script ↗

3. OpenCode 2.x Layers & Root Components

All frontend logic is isolated inside packages/opencode-vim/ using relative imports and SolidJS reactive graphs. Utilizing OpenCode 2's Keymap.createLayer for modal states and DialogIntegration for seamless UI popups.

Browse opencode-vim Source ↗V2 Migration Guide ↗

4. Unified Packaging & Quick Deployment

Compiled with Bun into single-file executable oc-vim, with symlink aliases oc and opencode-vim for complete CLI drop-in compatibility. Zero local Node.js or Bun environment needed to execute.

Build from Source

Get started with oc-vim.

Clone the repository and compile the standalone executable for your machine with a single command.

1. Clone Repository

Fetch the complete repository including fork frontend packages and history:

git clone https://github.com/iamcheyan/oc.git cd oc

2. Build & Launch

The build outputs the standalone executable under fork/dist/:

bash fork/build.sh ./fork/dist/oc-vim-linux-x64/bin/oc-vim
